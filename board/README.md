# 배치표 (경기과용)

경기과가 그날 배치표를 짜는 프로그램. **캐디 총무 앱과는 따로 도는 별개 프로그램이다.**
앱에는 "이 사람 누구요?"만 묻고, 배치표 데이터는 앱이 모른다.

## 생김새 — 기계 하나에 화면 둘

| 파일 | 무엇 |
|---|---|
| `core6.js` | ★기계 — 사실과 셈. 화면에 닿는 곳은 `paint() toast() resyncSheet() drawCfg() saveFlash()` 뿐 |
| `store6.js` | 저장·설정 보관 |
| `view6.js` | 컴퓨터 화면 |
| `view6m.js` | 휴대폰 화면 (아직 개발 중 — 아무 방에도 안 올린다) |
| `tpl6_head.html` · `tpl6m_head.html` | 각 화면의 껍데기와 색 |
| `board16_data.json` | 처음 켤 때 깔리는 본보기 배치표 |

## 짓기

```
python build7.py          # 둘 다
python build7.py pc       # 컴퓨터 것만
```
→ `C:\Users\ghdrn\Documents\board16.html` · `board16m.html`

## 고친 뒤에는 반드시 확인한다

한 번에 두 가지를 본다.

```
python runpc.py _probeXXX.html 1600 1000 1     # 컴퓨터 화면에서 재 본다
python runm.py  _probeXXX.html 390 844         # 휴대폰 화면에서
bash _regXX.sh                                 # 딴 데가 망가졌나 — 66가지를 짝지어 대 본다
```

- 점검 시험(`_probe*.html`) 290개가 있다. 화면을 진짜 브라우저에 띄워 놓고 눈으로 볼 값을 재는 것들이다.
- 묶음 점검(`_reg*.sh`)은 **고치기 전 것과 고친 뒤 것을 같은 시험으로 짝지어** 대 본다.
  기준이 되는 '고치기 전' 파일은 `C:\Users\ghdrn\Documents\board16*_XXbefore.html` 에 둔다(보관소에는 안 넣는다 — 너무 크다).
- **크롬 프로필이 겹치면 안 된다.** 묶음 점검이 도는 동안 새로 짓거나 다른 시험을 돌리지 않는다.

## 저장 글의 생김새

`store6.js` 의 `SCHEMA` 가 저장 글의 모양 번호다. **파일 이름(`BUILD`)과 떼어 놓았다** —
프로그램을 새로 올린다고 저장해 둔 배치표가 안 열리면 안 되기 때문이다.
모양을 바꾸는 날에만 `SCHEMA` 를 하나 올리고 `MIGRATE` 에 옮기는 길을 한 칸 적는다.
길을 안 적은 저장본은 **안 열리되 안 지워진다.**

## 규칙

- 이모지 금지. '탕' 이라는 말 금지(부·홀로 쓴다).
- 화면 바꾸는 일은 **시험용 사본을 먼저 보이고 승낙을 받은 뒤** 올린다.
- 배치표에는 캐디 실명이 그대로 보인다. **로그인 없는 자리에 두지 않는다.**
